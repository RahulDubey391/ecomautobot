Module 1: Production Playwright Architecture & Mental Models

Welcome to the foundational architecture module of The Playwright & E2E Testing Production Vault.

Most enterprise end-to-end test suites fail not because of browser-level bugs, but because of architectural decay. Common symptoms include: * Tests coupling directly to unstable CSS selectors. * Tests relying on arbitrary sleep timers (page.waitForTimeout(5000)). * Test runs polluting staging databases with orphaned records. * Teams building monolithic "God" Page Objects that become unmaintainable as products evolve.

This module provides the battle-tested architectural blueprint required to scale Playwright to thousands of daily runs across distributed CI/CD workers with zero non-deterministic failures (flakiness).

File Naming Conventions

  • Spec Files: <domain-or-feature>.<action>.spec.ts (e.g., subscription-swap.spec.ts).
  • Page Objects: <DomainName>Page.ts (e.g., BillingPage.ts).
  • Components: <ComponentName>Component.ts (e.g., TableComponent.ts).
  • Fixtures: <domain>.fixture.ts (e.g., auth.fixture.ts).
  • Factories: <model>.factory.ts (e.g., user.factory.ts).

Resilient tracing (captures only on first retry to minimize CI storage bloat). 2. Proper sharding support. 3. Isolated local webserver spinning vs. remote staging runs. 4. Clean separation of auth state artifacts (.auth/).

3. Scalable Page Object & Component Composition Architecture

Monolithic Page Objects where every single button, dropdown, and link on a dashboard lives within a single DashboardPage.ts class become unmaintainable.

Follow these two architectural rules: 1. Inherit from a strict BasePage that standardizes navigation, dynamic element polling, and assertion handling. 2. Decompose complex screens into Component Objects that are passed the root locator scope.

BasePage Architecture

// src/pages/BasePage.ts
import { Page, Locator, Response, expect } from '@playwright/test';

export abstract class BasePage {
  readonly page: Page;
  abstract readonly pagePath: string;

  constructor(page: Page) {
    this.page = page;
  }

  /**
   * Navigates directly to the page's declared relative path.
   */
  async navigate(queryParams?: Record<string, string>): Promise<Response | null> {
    const url = queryParams
      ? `${this.pagePath}?${new URLSearchParams(queryParams).toString()}`
      : this.pagePath;
    return this.page.goto(url, { waitUntil: 'domcontentloaded' });
  }

  /**
   * Asserts the current URL matches the expected pagePath pattern.
   */
  async verifyPath(): Promise<void> {
    await expect(this.page).toHaveURL(new RegExp(`${this.pagePath}`));
  }

  /**
   * Scopes locators strictly by data-test-id or accessible semantic ARIA roles.
   */
  getByTestId(id: string): Locator {
    return this.page.getByTestId(id);
  }

  /**
   * Resilient click handler that asserts stability before interaction.
   */
  async safeClick(locator: Locator): Promise<void> {
    await expect(locator).toBeVisible();
    await expect(locator).toBeEnabled();
    await locator.click();
  }
}

Component Object Model (Decoupled Sub-Views)

Components must never reference the global page directly when searching for internal child nodes. Always pass a parent Locator (root) into the component constructor to limit search scope.

// src/components/common/TableComponent.ts
import { Locator, expect } from '@playwright/test';

export class TableComponent {
  readonly rootLocator: Locator;
  readonly rows: Locator;
  readonly headers: Locator;

  constructor(rootLocator: Locator) {
    this.rootLocator = rootLocator;
    this.rows = this.rootLocator.locator('tbody tr');
    this.headers = this.rootLocator.locator('thead th');
  }

  async getRowCount(): Promise<number> {
    return this.rows.count();
  }

  getRowByColumnValue(columnIndex: number, value: string): Locator {
    return this.rows.filter({
      has: this.rootLocator.locator(`td:nth-child(${columnIndex})`, { hasText: value }),
    });
  }

  async clickRowAction(identifierValue: string, actionButtonTestId: string): Promise<void> {
    const targetRow = this.rows.filter({ hasText: identifierValue }).first();
    await expect(targetRow).toBeVisible();
    await targetRow.getByTestId(actionButtonTestId).click();
  }
}

Implementing the Page Object via Composition

// src/pages/dashboard/BillingPage.ts
import { Page, Locator, expect } from '@playwright/test';
import { BasePage } from '../BasePage';
import { TableComponent } from '../../components/common/TableComponent';

export class BillingPage extends BasePage {
  readonly pagePath = '/dashboard/billing';

  // Scoped Components
  readonly invoiceTable: TableComponent;

  // Page Specific Locators
  readonly currentPlanCard: Locator;
  readonly upgradePlanButton: Locator;
  readonly cancelSubscriptionButton: Locator;
  readonly billingStatusBadge: Locator;

  constructor(page: Page) {
    super(page);
    this.invoiceTable = new TableComponent(this.page.getByTestId('invoices-table-container'));
    this.currentPlanCard = this.page.getByTestId('current-plan-card');
    this.upgradePlanButton = this.page.getByRole('button', { name: /upgrade to pro/i });
    this.cancelSubscriptionButton = this.page.getByRole('button', { name: /cancel subscription/i });
    this.billingStatusBadge = this.page.getByTestId('subscription-status-badge');
  }

  async executePlanUpgrade(targetTier: 'pro' | 'enterprise'): Promise<void> {
    await this.safeClick(this.upgradePlanButton);
    const tierModalButton = this.page.getByRole('button', { name: new RegExp(`Confirm ${targetTier}`, 'i') });
    await this.safeClick(tierModalButton);
  }

  async assertPlanActive(expectedPlanName: string): Promise<void> {
    await expect(this.currentPlanCard).toContainText(expectedPlanName);
    await expect(this.billingStatusBadge).toHaveText(/active/i);
  }
}

4. Deterministic Test Data Seeding Strategy

The number-one cause of flaky, brittle CI runs is shared mutable state (e.g., three worker threads simultaneously modifying the same test account's settings).

Seeding Strategies Compared

Strategy Speed Isolation Level Implementation Cost Best Used For
Direct DB Seeding (Prisma / SQL) Ultra-Fast (~10ms) Maximum (Row-level) Medium (Schema coupling) Complex business state, bulk records
API Mutation Factory (request) Fast (~100ms) High (New entity per test) Low (Uses existing APIs) Standard user signup, org bootstrapping
UI-Driven Setup Slow (~3,000ms+) Low (High failure vectors) Lowest (No API/DB needed) Only for end-to-end registration validation

The Production Fixture Pattern

Do not write raw setup/cleanup logic inside beforeEach or afterEach blocks within test files. Encapsulate setup, teardown, and lifecycle execution entirely inside Playwright Custom Fixtures.

This guarantees that if a test fails midway through execution, Playwright's fixture teardown executes automatically, preventing database pollution.

// src/factories/user.factory.ts
import { cryptoRandomString } from '../utils/crypto';

export interface UserPayload {
  email: string;
  name: string;
  tenantSlug: string;
}

export function generateUserPayload(): UserPayload {
  const uniqueId = cryptoRandomString(8);
  return {
    email: `ci-worker-${process.env.TEST_WORKER_INDEX || '0'}-${uniqueId}@example-vault.internal`,
    name: `Test Engineer ${uniqueId}`,
    tenantSlug: `tenant-${uniqueId}`,
  };
}

// src/fixtures/base.fixture.ts
import { test as base, APIRequestContext, request } from '@playwright/test';
import { BillingPage } from '../pages/dashboard/BillingPage';
import { generateUserPayload, UserPayload } from '../factories/user.factory';

type WorkerTestContext = {
  // Test User context containing provisioned API tokens and metadata
  authedUser: {
    user: UserPayload;
    token: string;
    organizationId: string;
  };
  // Pre-instantiated Page Objects
  billingPage: BillingPage;
};

export const test = base.extend<WorkerTestContext>({
  // Automatic Isolated User Setup and Teardown
  authedUser: async ({}, use) => {
    // 1. Setup Phase: Spin up an out-of-band API context to rapidly provision an isolated tenant
    const apiContext: APIRequestContext = await request.newContext({
      baseURL: process.env.API_BASE_URL || 'http://localhost:3000/api',
    });

    const userPayload = generateUserPayload();

    // Create new organization + user account directly via internal API
    const response = await apiContext.post('/v1/testing/provision-tenant', {
      data: userPayload,
      headers: {
        'x-e2e-provision-secret': process.env.E2E_SEED_SECRET || 'secret-vault-key',
      },
    });

    if (!response.ok()) {
      throw new Error(`Failed to seed isolated tenant: ${await response.text()}`);
    }

    const { token, organizationId } = await response.json();

    // 2. Yield context to the test spec
    await use({
      user: userPayload,
      token,
      organizationId,
    });

    // 3. Teardown Phase: Runs automatically after test finishes (even if failed/timed out)
    const teardownResponse = await apiContext.delete(`/v1/testing/teardown-tenant/${organizationId}`, {
      headers: {
        Authorization: `Bearer ${token}`,
      },
    });

    if (!teardownResponse.ok()) {
      console.warn(`[Cleanup Warning]: Failed to delete tenant ${organizationId}`);
    }

    await apiContext.dispose();
  },

  // Fixture: Pre-conditioned page object with injected local auth state
  billingPage: async ({ page, authedUser }, use) => {
    // Inject auth token directly into browser storage to bypass manual UI login
    await page.addInitScript((jwt) => {
      window.localStorage.setItem('auth_token', jwt);
    }, authedUser.token);

    const billingPage = new BillingPage(page);
    await use(billingPage);
  },
});

5. Zero-Flakiness Network Interception & Mocking Rules

Mocks are a double-edged sword. Over-mocking leads to tests passing while production breaks. Under-mocking introduces failures from external third parties (e.g., Stripe, SendGrid, Segment).

The Enterprise Mocking Matrix

[ Incoming Request ]
        │
        ├── Is it an External 3rd Party? (Stripe, Twilio, Datadog)
        │       └── YES ──> ALWAYS INTERCEPT & MOCK (Rule 1)
        │
        ├── Is it a Slow Non-Critical Telemetry Endpoint? (Analytics)
        │       └── YES ──> ABORT / FULFILL INSTANTLY (Rule 2)
        │
        └── Is it Core Application Architecture? (Your Primary API)
                ├── Happy Path ──> HIT REAL API / SEEDED DB
                └── Edge Failure (500 Error, 429 Rate Limit) ──> INTERCEPT & ROUTE-MOCK

Network Mocking Implementation (Stripe & Analytics)

Never leak analytics data to production warehouses during CI, and never hit live credit card processors inside parallel execution loops.

// src/network/handlers/network.fixture.ts
import { test as baseTest } from '../fixtures/base.fixture';

export const test = baseTest.extend({
  page: async ({ page }, use) => {
    // Rule 1: Silence third-party analytics telemetry (reduces CPU/network load)
    await page.route(/.*(segment\.io|google-analytics\.com|posthog\.com).*/, (route) => {
      route.abort();
    });

    // Rule 2: Intercept Payment Gateway (Stripe Tokenization)
    await page.route('https://api.stripe.com/v1/tokens', async (route) => {
      if (route.request().method() === 'POST') {
        await route.fulfill({
          status: 200,
          contentType: 'application/json',
          body: JSON.stringify({
            id: 'tok_1N4TestMockedToken890',
            object: 'token',
            card: {
              id: 'card_1N4TestCardMocked',
              brand: 'Visa',
              last4: '4242',
              exp_month: 12,
              exp_year: 2030,
            },
          }),
        });
      } else {
        await route.continue();
      }
    });

    // Provide the clean, intercepted page to the tests
    await use(page);
  },
});

Deterministic HAR Recording for Volatile Services

For services you cannot easily mock manually, use Playwright's HAR routing to capture real responses once and replay them deterministically in CI:

// In spec file: Replay cached network responses locally or in CI
await page.routeFromHAR('./src/network/mocks/exchange-rates.har', {
  url: '**/api/v1/forex/rates',
  update: false, // Set to TRUE to record and refresh the HAR file
  notFound: 'fallback',
});

7. Execution: Writing the Production Spec

Here is how all these architectural components compose into a clean, deterministic, self-contained end-to-end test spec.

// tests/billing/subscription-swap.spec.ts
import { test, expect } from '../../src/network/handlers/network.fixture';

test.describe('Billing & Subscription Upgrades', () => {
  test('User can upgrade subscription from Starter to Pro via Stripe checkout', async ({
    billingPage,
    authedUser,
  }) => {
    // 1. Direct page navigation using the composed Page Object
    await billingPage.navigate();
    await billingPage.verifyPath();

    // 2. Validate current state matches the seeded tenant state
    await billingPage.assertPlanActive('Starter');

    // 3. Execute upgrade transaction (uses intercepted Stripe tokens)
    await billingPage.executePlanUpgrade('pro');

    // 4. Assert UI state has transitioned to upgraded tier
    await billingPage.assertPlanActive('Pro');

    // 5. Assert Table Component dynamically reflects newly generated invoice
    const targetInvoiceRow = billingPage.invoiceTable.getRowByColumnValue(2, 'Pro Plan Upgrade');
    await expect(targetInvoiceRow).toBeVisible();
    await expect(targetInvoiceRow).toContainText('$49.00');
  });

  test('Billing history renders empty state gracefully for fresh tenant', async ({
    billingPage,
  }) => {
    await billingPage.navigate();
    const rowCount = await billingPage.invoiceTable.getRowCount();

    // Fresh tenant fixture has no historical transactions
    expect(rowCount).toBe(0);
    await expect(billingPage.page.getByTestId('empty-invoices-notice')).toBeVisible();
  });
});

8. Enterprise Production Checklist

Before running tests across a multi-worker environment, ensure every item on this checklist is satisfied.

  • [ ] No Hardcoded Sleep Timers: All calls to page.waitForTimeout() are eliminated. Only use locator assertions with auto-waiting (expect(locator).toBeVisible()).
  • [ ] Dynamic Selectors Removed: No selectors depend on unstable Tailwind classes (e.g., css=div.flex.items-center.py-2). All locators use getByTestId(), getByRole(), getByLabel(), or getByText().
  • [ ] Data Mutation Isolation: Every test suite provisions its own tenant context or uses deterministic factories. No tests mutate records utilized by parallel suites.
  • [ ] Clean Tear-Down: All created testing records register a corresponding deletion hook inside the fixture lifecycle.
  • [ ] Mock Non-Deterministic Third Parties: All third-party trackers, SMS providers, external payment bridges, and auth verification endpoints are strictly intercepted via page.route().
  • [ ] Tracing Strategy Configured: Tracing is set to 'on-first-retry' to prevent massive CI artifact bloat while preserving debugging data for genuine failures.
  • [ ] No Shared Browser Contexts: Every test gets an isolated context (context fixture). Storage state is injected via page.addInitScript() or dedicated .auth JSON profiles, never through manual UI logins in beforeEach.
